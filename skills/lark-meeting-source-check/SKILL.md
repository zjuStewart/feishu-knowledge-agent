# 最近纪要来源核验

“权限可读”和“是最近会议”是两种证据。权限验证得到的历史样本、知识库现有副本、先前摘要，不能作为最近纪要的选择依据。对这一任务先运行来源核验，再进行内容处理。

## 启动前核验

使用个人配置 `~/.config/lark-meeting-source-check/profile.json`，执行一次：

```bash
python3 <本 Skill 目录>/scripts/prepare_latest.py
```

用户明确给出会议日期时加 `--expected-date YYYY-MM-DD`；未给出时由实际通知与原文确定，不填旧样本日期。也支持 `--config /绝对路径/profile.json`。

脚本使用现有 CLI 的 user 身份，实时读取配置中本人智能纪要助手的完整可见通知，包含文本链接和卡片，不添加旧关键词、旧日期范围。分页不完整则失败。它核验候选原文的文档ID、标题日期、会议开始时间、版本与通知时间：默认“最近会议”按实际会议开始时间选择；最近收到的旧会议补发不会覆盖较新的会议。无日期的文档、不可读候选、矛盾日期和并列不同会议会停止；不得为了继续处理而退回旧材料。

成功输出包含 `purpose=latest_meeting_selection`、核验时间、来源ID、会议时间、通知时间、版本和正文指纹。只有本次命令成功，输出目录的 `source-status.json` 为成功，且核验时间距当前不超过10分钟，才可以用其 `source-manifest.json` 启动整理或云端回放。复用过期记录前重新运行。禁止手写一个旧来源来替代失败结果。

启动下游任务前执行 `python3 <本 Skill 目录>/scripts/prepare_latest.py --verify-receipt`；该校验检查成功状态、用途、配置归属、时效及保留正文的指纹和版本。显式配置时继续加同一个 `--config`。退出码非0或 `ok=false` 则不启动，不只靠 Agent 口头判断。

给后续 Agent 传递同一份已核验来源记录及其 `cloud_source_instruction`，要求它实际读取指定文档并检查ID、日期、版本，不再自行猜“上一份”。管理、内容等角色共用该来源。内容变更时重新核验，不拿旧版报告当新报告。

“最近收到的纪要”与“最近发生的会议”不一致时说明两个时间，再按用户明确的语义处理；本脚本默认最近发生的会议，不能隐藏补发的区别。真实新会议事件则直接使用事件绑定的来源ID，不做最近会议搜索。业务整理、归档预览和用户确认仍走现有会议工作流；本 Skill 不执行归档或消息推送。

## 独立配置与运行限制

个人配置只含本人智能纪要助手私聊ID、助手bot ID、飞书域名和本地输出位置。示例见 [profile.example.json](assets/profile.example.json)。每人单独授权、配置，不共享别人的访问身份。脚本仅执行消息和文档读取，不读取或配置模型 Key；目录与正文读取本身不调用模型。

遇到宿主限制系统钥匙串访问时，走其正规的命令授权机制；不要读取密钥或改变凭据存储方式。认证问题使用已有的 `lark-shared` 能力，仅报告需要用户处理的动作，禁止自动重新授权。

本地 CLI 入口已用当前账号验收。云端 Agent 无法运行本地脚本时，把同样的来源绑定与日期核验要求写进其任务；不把云端提示词当成已经部署的程序拦截器，也不声称所有 Agent 都不会犯错。
