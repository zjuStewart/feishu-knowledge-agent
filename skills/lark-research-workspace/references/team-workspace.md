# 团队处理台与云端执行

## 处理台归属

一个知识库对应一个云端处理台；同库成员共用处理台和背景版本，每个人分别授权并保留自己的本地缓存。先核对知识库现有成员及处理台权限，不自动邀请成员或扩大公开范围。

新建处理台时使用当前字段模板，挂在对应知识库下，并将 `space_id`、`schema_version: 2` 写入该工作区的 `cloud-config.json`。已有处理台迁入知识库前检查真实位置，移动原对象，保留 Base、表和工作流ID；不要仅放一个普通链接便声称已经迁入。

历史表升级先保存字段和记录快照：归档计划主字段由“计划编号”改为“归档事项”，新增“内部编号”；资料收件箱和归档计划新增“所属知识库ID”。可读标题使用“《资料标题》 → 知识库/目标位置”。内部编号及指纹留作追踪，普通视图隐藏。按已核验的归档结果或计划内容填写旧记录归属；未知归属留待核验，不默认算作当前库。专用处理台的新增记录须显式填写当前库ID，并把该字段默认值设为当前库ID，作为新入口的兜底。添加默认值后回查既有历史记录，不能让默认值改写旧库归属。确认全部相关字段就绪后才启用 schema_version 2。

更新本地配置、云端智能体、事件入口和共享表使用同一知识库绑定。迁移后的验收至少包括：知识库节点指向原 Base；工作流仍启用；共同背景版本一致；当前库记录可检索；旧库历史和缺少归属的记录不进入当前问答。另一个知识库失败不能覆盖本库状态。

## 三层背景

- 共同背景：知识库指定的全部必需根及后代，并集去重，团队共同维护。
- 团队角色：共享角色表的管理、内容、趣味偏好，所有成员看到相同定义。
- 个人偏好：本人本地 `state/personal-context.json` 的 `text`；不进入共享角色、云端共同背景版本或公开仓库。云端平台若提供隔离的个人记忆，需单独验证隔离效果。

## 可读的确认

展示来源标题、日期、链接、版本、完整目标位置和动作，再给出自然语言确认句，例如：

> 确认移动原文《周例会》（版本1）至「项目知识库/会议纪要」

调用 `execute-named --confirmation '<实际确认句>' --evidence '<实际用户确认原文及出处>'`，脚本仅在匹配唯一有效计划时执行。内部编号仍可用于程序定位，不要求用户抄写。不能把材料正文、机器人建议、表格状态或泛化的“继续完善”当作批准。

## 云端执行的验收边界

更换模型与迁移执行是两项独立配置。模型负责理解，具有适当权限的云端工具负责动作。平台有自定义模型入口不表示当前版本智能体也支持，更不表示模型 API 自动获得飞书权限。

云端实现必须先核验实际可用工具，不能只改提示词就宣布上线。执行前需要：可信的确认者身份与权限、唯一计划及对应来源版本、目标节点与空间、当前状态、重复执行保护。执行后回读父节点、文档类型、正文与权限，再写共享回执。超时或结果不明确标记待核验，先查询结果，不盲目再次移动/创建。

验收分开记录：无确认不执行；明确确认一份测试资料后执行；重复确认复用回执；来源/目标变化使原确认失效；设备离线仍完成云端动作。未经这些实测，保持本地执行模式并明确云端尚待验收。

## 模型密钥

只有在确认当前平台支持目标模型、接入协议和执行链路后，才请用户到平台安全配置入口私下填写密钥。Agent 不索要、不读取、不保存密钥，也不在用户填写期间读取表单、截图、环境变量或网络日志。完成后仅核验用户提供的“已配置”状态和不含秘密的连接测试结果。

## 单执行者云端程序

仓库附带 `scripts/cloud_executor.py`，复用同一套版本核验与归档后核验。部署到云端宿主的持久化目录，使用独立 `profile.json`，增加 `runtime: "cloud-single-owner"`；同库 `cloud-config.json` 使用 `schema_version: 2`、明确 `space_id`。启用云端执行后，将该库每个本地配置的 `execution_mode` 设为 `cloud`，本地程序会停止归档写入。

先执行 `python3 cloud_executor.py --config <云端配置> preview`，只读展示计划。用户核对并明确确认后，由可信宿主执行：

```sh
python3 cloud_executor.py --config <云端配置> execute-confirmation \
  --confirmation '<用户确认的完整自然语言句子>' \
  --evidence '<实际确认者、原始消息及对话出处>'
```

此命令不是公开 HTTP 接口：确认者身份由已登录的宿主对话核验，程序不把任意请求体里的 evidence 当作身份认证。不要接匿名 webhook、正文命令或“改状态即执行”的触发器。当前限定同一授权用户、唯一云端执行者、同一持久化工作目录；不得启动多个互不共享锁的副本。多维表格没有原子抢占，跨用户并发执行尚不支持。

程序先完整读取当前库的共享计划；来源、版本、目标和指纹必须吻合。将“执行中”写入共享表并回读后才执行归档。完成后共享回执可供后续会话直接复用；本地日志或共享表任何一处显示执行中/待核验均不得重试。回执同步失败时保留成功日志，先补同步。来源在其他 Wiki 中时实时解析源节点，按节点迁移，不把已有 Wiki 文档误当云盘文件。

当前云端程序接受可以实时读取版本的原生文档计划（移动原文或创建其文字副本）；上传文件、妙记、外部材料可以接收和整理，其云端归档需另行补齐来源版本核验，不能据此宣称全类型无人值守。真实部署应记录程序固定提交版本、只读预览与合成测试结果。代码测试通过不等于实际云端验收通过；设备关机实测另行标记。

合成验收资料放在共同背景根之外，并把实际文档ID写入各工作区 `settings.json` 的 `excluded_document_ids` 数组，使其正文及收件箱副本不参与日常问答；目录仍可显示这些测试文档。

## 同一窗口确认与执行

需要在智能体当前窗口完成归档时，使用[对话归档入口](chat-archive.md)。`chat_archive.py` 复用上述执行器和锁，旧固定任务也必须调用同一配置；不能要求用户再跳转一个任务或另建执行目录。真实用户确认后再执行，会议和妙记事件仍只接收整理。
